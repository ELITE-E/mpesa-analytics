# mpesa-analytics

Skeleton (CP0): guards, config, tooling and a probe page only. There is no product code yet.
All data in this repo is synthetic and generated by this repo.

## Setup

    uv sync
    npm ci                                  # ESLint and Prettier, dev only
    uv run python tools/vendor.py fetch     # pinned runtime, gitleaks and node, gitignored
    uv run pre-commit install

## Checks

    uv run pytest                           # guard tests; violations are planted in temp dirs
    uv run pre-commit run --all-files       # the fast checks; CI runs everything
    node tools/run_pyodide_tests.mjs        # imports the core under Pyodide

## Map

| Folder | What it holds |
|---|---|
| `.github/` | CI workflow and the PR template with the review checklist |
| `docs/` | Architecture, coding standards and glossary |
| `docs/decisions/` | Architecture decision records and the change logs |
| `pdf_reader/` | Browser side: the pdf.js adapter, its worker and the bridge to Python |
| `src/mpesa_core/` | The pure Python core, shipped as a wheel; `contracts`, `errors`, `pipeline` and `bridge` sit here |
| `src/mpesa_core/extraction/` | Statement pages to raw rows: column calibration and row building |
| `src/mpesa_core/cleaning/` | Raw rows to canonical rows |
| `src/mpesa_core/classification/` | Canonical rows to transactions, with entities |
| `src/mpesa_core/analysis/` | Transactions to the report |
| `src/mpesa_core/reconciliation/` | Reconciliation, attestation and transaction identity |
| `tests/core/` | Core tests, run under CPython and Pyodide |
| `tests/pdf_readers/` | Node tests of the pdf.js adapter and Python tests of both PDF readers |
| `tests/equivalence/` | Tests of the old-against-new comparison tools |
| `tests/guards/` | Tests of the guards, with violations planted in temp dirs |
| `tests/synth/` | Tests of the synthetic generator and its ledger |
| `tests/fixtures/synthetic/` | Generated fixtures, each listed with its seed in `MANIFEST.toml` |
| `tools/guards/` | The guards and their configuration |
| `tools/pdf_readers/` | Recording, profiling and extraction tools for PDF readers, and the dev-only pdfplumber reader |
| `tools/synth/` | Synthetic statement generator and independent ledger |
| `tools/equivalence/` | Layout profile, baseline export and comparison, run by the owner on a real statement |
| `web/probe/` | The pandas load probe |
| `web/public/` | Static files; `vendor/` holds the fetched runtime and is gitignored |
| `web/src/` | The front end |
| `web/tests/`, `web/e2e/` | Front-end tests. They stay in `web/` because they use the front end's own toolchain |

Guards print file names and counts, never matched text. See
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/CODING_STANDARDS.md](docs/CODING_STANDARDS.md),
[docs/glossary.md](docs/glossary.md) and [docs/decisions/](docs/decisions/).
