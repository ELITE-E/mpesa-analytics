# mpesa-analytics

Reads an M-PESA statement PDF in the browser and shows where the money went. Nothing leaves the
device: the PDF is read by pdf.js and a Python core under Pyodide in a worker, and the app is a
static export served with a strict CSP. All data in this repo is synthetic and generated by this repo.

## Remember on this device

Off by default: a statement read without it is forgotten when the page reloads. Turned on in
"Saved data" (`/settings`), statements are saved in this browser, encrypted with a passphrase
(WebCrypto, ADR 0016), one ledger per M-PESA account, merged statement by statement after the
person confirms the counts on the merge screen (ADR 0017). It locks after 10 idle minutes and on a
reload; there is no recovery for a forgotten passphrase, only delete-all. What the lock protects,
and what it does not, is in [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).

## Setup

    uv sync
    npm ci                                  # ESLint and Prettier, dev only
    uv run python tools/vendor.py fetch     # pinned runtime, gitleaks and node, gitignored
    uv run pre-commit install

## Checks

    uv run pytest                           # guard tests; violations are planted in temp dirs
    uv run pre-commit run --all-files       # the fast checks; CI runs everything
    node tools/run_pyodide_tests.mjs        # imports the core under Pyodide
    uv build --wheel --out-dir dist && uv run python tools/vendor.py runtime --wheel dist/mpesa_core-0.0.0-py3-none-any.whl
    node --test --test-concurrency=1 tests/browser/*.test.js   # the engine in real Chrome
    npm run build --prefix web                                  # the app, as a static export (web/out)
    cd web && node --import ./tests/support/register.mjs --test tests/*.test.mjs tests/*.test.ts   # the web app; the *-chrome, e2e and remember-e2e files need Chrome and the build

## Limits

Desktop limits come from measuring the synthetic F-LARGE statement in Chrome (`pdf_reader/limits.js`, `docs/decisions/cp8-notes.md`). Phone unverified: no limit has been measured on a phone.

## Map

| Folder | What it holds |
|---|---|
| `.github/` | CI workflow and the PR template with the review checklist |
| `docs/` | Architecture, coding standards and glossary |
| `docs/decisions/` | Architecture decision records and the change logs |
| `pdf_reader/` | Browser side: the pdf.js adapter, its worker and the bridge to Python |
| `src/mpesa_core/` | The pure Python core, shipped as a wheel; `contracts`, `errors`, `pipeline` and `bridge` sit here |
| `src/mpesa_core/extraction/` | Statement pages to raw rows: column calibration and row building |
| `src/mpesa_core/cleaning/` | Raw rows to canonical rows |
| `src/mpesa_core/classification/` | Canonical rows to transactions, with entities |
| `src/mpesa_core/analysis/` | Transactions to the report |
| `src/mpesa_core/reconciliation/` | Reconciliation, attestation and transaction identity |
| `tests/core/` | Core tests, run under CPython and Pyodide |
| `tests/pdf_readers/` | Node tests of the pdf.js adapter and Python tests of both PDF readers |
| `tests/equivalence/` | Tests of the old-against-new comparison tools |
| `tests/guards/` | Tests of the guards, with violations planted in temp dirs |
| `tests/synth/` | Tests of the synthetic generator and its ledger |
| `tests/fixtures/synthetic/` | Generated fixtures, each listed with its seed in `MANIFEST.toml` |
| `tools/guards/` | The guards and their configuration |
| `tools/pdf_readers/` | Recording, profiling and extraction tools for PDF readers, and the dev-only pdfplumber reader |
| `tools/synth/` | Synthetic statement generator and independent ledger |
| `tools/equivalence/` | Layout profile, baseline export and comparison, run by the owner on a real statement |
| `web/probe/` | The pandas load probe |
| `web/harness/` | The bare CP8a engine harness and its CSP test server; CP8b replaces it |
| `tools/browser/` | Shared real-Chrome session for the browser tests and tools |
| `tools/probes/` | Owner-run probes that print yes or no only |
| `tests/browser/` | Real-Chrome tests of the statement engine (Playwright, system Chrome) |
| `web/public/` | Static files; `vendor/` holds the fetched files and `runtime/` the checksummed runtime the browser loads, both gitignored |
| `web/src/` | The front end: screens (`app/`), components, copy (`content/`) and the data layer (`data/repo.ts`) |
| `web/src/persistence/` | "Remember on this device": the encrypted vault and the ledger store (ADR 0016, ADR 0017) |
| `web/src/lib/remember.ts` | The screens' handle on remembering: turn on, unlock, lock, delete-all, switch ledgers |
| `web/tests/`, `web/e2e/` | Front-end tests. They stay in `web/` because they use the front end's own toolchain |

Guards print file names and counts, never matched text. See
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/CODING_STANDARDS.md](docs/CODING_STANDARDS.md),
[docs/glossary.md](docs/glossary.md) and [docs/decisions/](docs/decisions/).
