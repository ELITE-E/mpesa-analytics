# mpesa-analytics

Reads an M-PESA statement PDF in the browser and shows where the money went. Nothing leaves the
device: the PDF is read by pdf.js and a Python core under Pyodide in a worker, and the app is a
static export served with a strict CSP. All data in this repo is synthetic and generated by this repo.

Not affiliated with Safaricom. M-PESA is a trademark of its owner; this project is independent
(`docs/NAMING.md`).

## Remember on this device

Off by default: a statement read without it is forgotten when the page reloads. Turned on in
"Saved data" (`/settings`), statements are saved in this browser, encrypted with a passphrase
(WebCrypto, ADR 0016), one ledger per M-PESA account, merged statement by statement after the
person confirms the counts on the merge screen (ADR 0017). It locks after 10 idle minutes and on a
reload; there is no recovery for a forgotten passphrase, only delete-all. What the lock protects,
and what it does not, is in [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).

## What is stored when Remember is on

- **Off (the default):** nothing. The statement is read in the page's memory and forgotten on a
  reload or when the tab closes.
- **On:** the transactions of each statement you confirm, merged into one ledger per M-PESA
  account, in this browser's IndexedDB, encrypted (AES-GCM, 256-bit key from your passphrase by
  PBKDF2-SHA256, 600,000 rounds). Beside them, unencrypted: the salt and round count, each
  ledger's keyed-hash name, its size and save counter, a key check, and your hint if you set one
  (plain text, shown only after a wrong passphrase).
- **Never, on or off:** the PDF, its password, the statement's verification code, the account
  digest, your mobile number, name or email address, and the passphrase or key. The store refuses
  anything that carries them.
- **Delete all saved data** removes every ledger, the salt, the hint and the settings, and works
  while locked. The PDF files and CSV exports you saved yourself are not touched.

What the lock protects, and what it does not: [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).

## Setup

    uv sync
    npm ci                                  # ESLint and Prettier, dev only
    uv run python tools/vendor.py fetch     # pinned runtime, gitleaks and node, gitignored
    uv run pre-commit install

## Checks

    uv run pytest                           # guard tests; violations are planted in temp dirs
    uv run pre-commit run --all-files       # the fast checks; CI runs everything
    node tools/run_pyodide_tests.mjs        # imports the core under Pyodide
    uv build --wheel --out-dir dist && uv run python tools/vendor.py runtime --wheel dist/mpesa_core-1.0.0-py3-none-any.whl
    node --test --test-concurrency=1 tests/browser/*.test.js   # the engine in real Chrome
    npm run build --prefix web                                  # the app, as a static export (web/out)
    cd web && node --import ./tests/support/register.mjs --test tests/*.test.mjs tests/*.test.ts   # the web app; the *-chrome, e2e and remember-e2e files need Chrome and the build

## Limits

- **Desktop only.** Limits come from measuring the synthetic F-LARGE statement in desktop Chrome
  (`pdf_reader/limits.js`, `docs/decisions/cp8-notes.md`); other browsers are untested.
- **Phone unverified.** No limit or timing has been measured on a phone (`docs/ROADMAP.md`).
- **About 24% of rows are uncategorised.** On the owner's real statement, 1,386 of 5,698 rows
  (24%) match no classifier rule (`docs/decisions/equivalence-results.md`); the app counts them.
- **The first import takes about a minute**, longer for a long statement: the runtime and pandas
  load first (a cold 98-page synthetic statement took 44.8 s in Chrome, `cp8-notes.md`).
- **Consistency checks are not proof of authenticity.** Balance chains and summary totals that
  agree show the rows were read consistently, not that the statement is genuine.
- **Verification:** the app shows the verification instruction as printed on the statement; to
  check a statement is genuine, follow that instruction.
- After a first visit the app works offline: a hand-written service worker keeps only the app's
  own files (ADR 0018). CSV exports are not encrypted.
